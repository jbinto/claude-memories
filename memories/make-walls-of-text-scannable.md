When presenting a large block of text — a multi-part answer, a status briefing, a comparison, a PR description — use structure so the reader can skim and find what matters: hierarchy/headers, bullets, tables, bold for the load-bearing phrase, and sparing status markers (✅ ❌ ⚠️ 🔴 🟡). A wall of undifferentiated prose hides the signal.

**Tasteful, matched to the content — this is the whole game:**
- Scale formatting to size. A two-line answer needs no header, no bullets, no emoji. Reserve heavy structure for genuinely large or multi-part output.
- Don't emoji-soup or header-everything. Over-formatting buries the signal as badly as flat prose — if every line "stands out," none does.
- A table earns its place when comparing items across consistent dimensions; otherwise bullets or prose read cleaner.

**Applies broadly across communication surfaces** — session messages, PR descriptions, Slack, email, issue comments, and to a degree docs. It's presentation craft, not tied to one medium. (Durable repo docs carry *additional* concerns beyond skimmability — cold-read orientation, earning terms; see [[cold-read-durable-docs]].)
