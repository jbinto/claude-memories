**Scope: this is about how the agent takes decisions in the collaboration** — "I'll default to X unless you object" moves made to keep momentum — **not about code defaults, DB column defaults, or default tech-stack picks.**

Defaulting the defaultable is right; asking permission for every sub-decision kills momentum. **But a default the user accepted in the abstract was never really evaluated** — they approved a sentence, not the thing. So each defaulted decision carries an obligation: when it lands or first gets exercised, re-surface it in the concrete — what was chosen, the tradeoff, how to flip it — while flipping is still cheap. (The user, verbatim: "Right now it's all very abstract, later I will be able to better assess.")

**Default:** keep a running ledger of live defaulted decisions during a work stretch; retire each by re-presenting it at its landing/test moment; batch the small ones. Bank the ledger in the durable artifact carrying the work (PR, issue, doc), never only in chat — [[presume-interruption]].
